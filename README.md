# أسماء الله الحسنى

موقع وتطبيق أندرويد لأسماء الله الحسنى: ٩٩ مربعًا، لكل اسم معناه مفصلًا من كتب أهل السنة، وكيفية التعبد لله به، ودليله ودعاء مناسب. فيه تنبيه يومي بوقت تضبطه، وحفظ PDF، ومفضلة، وبحث، ووضع فاتح وداكن. يعمل بلا إنترنت ولا يجمع أي بيانات.

ما في هذا المجلد:

| المسار | الوظيفة |
|---|---|
| `www/` | الموقع نفسه (HTML وCSS وJS بلا إطار عمل) |
| `www/data/` | نصوص الأسماء التسعة والتسعين |
| `capacitor.config.json` | اسم التطبيق ومعرّفه `com.asmaallah.husna` |
| `.github/workflows/` | ثلاثة سير عمل: نشر الموقع، بناء الـ APK، إنشاء مفتاح التوقيع |
| `scripts/` | سكربتات الخطوط والأيقونات وتعديل مشروع الأندرويد |
| `android-res/` | أيقونات الأندرويد وأيقونة الإشعار |
| `store/` | أيقونة 512 ولقطات الشاشة ونصوص الوصف لرفعها على APKPure |

مشروع الأندرويد (`android/`) لا يُحفظ في المستودع، بل يُولَّد تلقائيًا عند كل بناء، فلا تحتاج Android Studio ولا حاسوبًا.

---

## الخطوة 1: ارفع المشروع إلى GitHub

1. أنشئ مستودعًا جديدًا على github.com (اسمه مثلًا `asma-allah-husna`)، عامًّا (Public) ليعمل الموقع مجانًا.
2. ارفع كل محتويات هذا المجلد، **ومعها المجلد المخفي `.github`**.

   **من الحاسوب (الأسهل):** فُكّ الضغط، ثم من صفحة المستودع اختر Add file ← Upload files واسحب كل الملفات والمجلدات إلى الصفحة، بما فيها `.github`. إن لم يظهر المجلد المخفي في مدير الملفات، فعّل «إظهار الملفات المخفية».

   **بـ git:**
   ```bash
   cd asmaa-allah-app
   git init && git add -A && git commit -m "الإصدار الأول"
   git branch -M main
   git remote add origin https://github.com/اسمك/asma-allah-husna.git
   git push -u origin main
   ```

   **من الجوال، إن تعذّر رفع المجلد المخفي:** ارفع الباقي، ثم من Add file ← Create new file اكتب في خانة الاسم `.github/workflows/pages.yml` والصق محتوى الملف المقابل، وكرّر لـ `build-apk.yml` و`make-keystore.yml`.

## الخطوة 2: شغّل الموقع (GitHub Pages)

1. من المستودع: Settings ← Pages ← في Source اختر **GitHub Actions**.
2. اذهب إلى تبويب Actions، وافتح «نشر الموقع (GitHub Pages)» ثم Run workflow (أو يعمل تلقائيًا عند أي رفع إلى `main`).
3. بعد دقيقتين يظهر الرابط: `https://اسمك.github.io/asma-allah-husna/`

رابط سياسة الخصوصية لـ APKPure هو الرابط نفسه تتبعه `privacy.html`.

## الخطوة 3: أنشئ مفتاح التوقيع (مرة واحدة فقط)

APKPure يطلب ملفًا موقّعًا، وكل تحديث لاحق لازم يُوقَّع بالمفتاح نفسه. **إن ضاع المفتاح لن تستطيع تحديث التطبيق.**

1. Actions ← «إنشاء مفتاح التوقيع» ← Run workflow.
2. عند انتهائه افتح التشغيل ونزّل الملف `signing-key-SAVE-THIS` من قسم Artifacts. فكّ ضغطه، ففيه:
   - `asma-release.jks` وهو المفتاح. **احفظ نسخة منه خارج GitHub** (بريدك أو تخزين سحابي خاص).
   - `KEYSTORE_BASE64.txt` و`اقرأني.txt` وفيهما القيم.
3. من المستودع: Settings ← Secrets and variables ← Actions ← New repository secret، وأضف أربعة أسرار:

   | الاسم | القيمة |
   |---|---|
   | `KEYSTORE_BASE64` | محتوى `KEYSTORE_BASE64.txt` كاملًا |
   | `KEYSTORE_PASSWORD` | من `اقرأني.txt` |
   | `KEY_ALIAS` | `asma` |
   | `KEY_PASSWORD` | من `اقرأني.txt` |

4. احذف الـ artifact من صفحة التشغيل (ينتهي تلقائيًا بعد يوم).

بديل بدون GitHub: على حاسوب فيه Java شغّل `bash scripts/make-keystore.sh` وسيطبع لك القيم نفسها.

## الخطوة 4: ابنِ ملف APK

أسهل طريقة: Actions ← «بناء ملف APK» ← Run workflow ← اكتب رقم الإصدار (مثل `1.0.0`).

أو أنشئ وسمًا:
```bash
git tag v1.0.0 && git push origin v1.0.0
```
وبعد نحو ٦ إلى ١٠ دقائق تجد الملف `Asma-Allah-Husna-1.0.0.apk` في:
- صفحة التشغيل ← Artifacts، أو
- تبويب Releases، إن استخدمت الوسم.

سير العمل يتحقق بنفسه من صحة التوقيع بـ `apksigner` قبل رفع الملف.

## الخطوة 5: انشر على APKPure

1. أنشئ حساب مطوّر من https://www.apkpure.com/developer وفعّل بريدك.
2. اختر Submit New App وارفع ملف الـ APK.
3. املأ البيانات من `store/listing.md`: الاسم والوصف والفئة، وأيقونة `store/icon-512.png`، و٣ لقطات على الأقل من `store/screenshots/`، ورابط سياسة الخصوصية من الخطوة 2.
4. أرسل للمراجعة، وتصلك النتيجة على البريد.

الخطوات أعلاه مأخوذة من مقال لطرف ثالث، وليست من وثائق APKPure الرسمية. إن اختلف النموذج عندك فالنموذج هو المرجع.

## التحديثات

عدّل الملفات، وارفع، ثم أعد الخطوة 4 برقم إصدار أكبر. رقم الإصدار الداخلي (`versionCode`) يزيد تلقائيًا مع كل بناء. استخدم المفتاح نفسه دائمًا.

## تخصيصات شائعة

- **معرّف التطبيق** (`com.asmaallah.husna`): إن أردت معرّفًا يخصك، غيّر `appId` في `capacitor.config.json` **قبل أول بناء**. تغييره بعد النشر يجعله تطبيقًا مختلفًا.
- **النصوص:** في `www/data/names1.js` و`names2.js` و`names3.js`. لكل اسم الحقول: `m` المعنى، و`w` ثلاثة بنود للتعبد، و`d` الدعاء، و`r` موضع الدليل.
- **الألوان:** المتغيرات في أعلى `www/styles.css`، وألوان المربعات في `PAL` داخل `www/app.js`.
- **عدد أوقات التنبيه:** الحد الأقصى ثلاثة في `addTime` داخل `www/app.js`.

## كيف يعمل التنبيه

- **في تطبيق أندرويد:** تُجدول تنبيهات محلية لـ ٤٥ يومًا قادمة، لكل يوم اسمه ومعناه المختصر، وتعمل والتطبيق مغلق وتُعاد جدولتها بعد إعادة تشغيل الجهاز. تتجدد القائمة كلما فتحت التطبيق. على أندرويد ١٢ وما بعده قد تحتاج السماح بـ «المنبهات والتذكيرات» من إعدادات التطبيق ليصل التنبيه في الدقيقة المضبوطة تمامًا، وسيظهر لك تنبيه بذلك.
- **في الموقع:** يصل التنبيه ما دامت الصفحة مفتوحة، فالمتصفحات لا تسمح بجدولة تنبيه بعيد المدى بلا خادم.

## ما اختُبر وما لم يُختبر

اختُبر في متصفح: ظهور ٩٩ مربعًا، البحث، بطاقة التفاصيل، المفضلة والحفظ، الوضع الداكن، جدولة التنبيه وإطلاقه في وقته، وتوليد ملف PDF كامل (١٠٢ صفحة A4) وفحصه.

**لم يُختبر هنا:** بناء الـ APK نفسه وتشغيله على جهاز أندرويد، لأن بيئة الإعداد لم تسمح بتنزيل أدوات أندرويد. سكربت تعديل المشروع اختُبر على قالب مماثل، وسير العمل مبني على الأوامر المعتمدة لـ Capacitor 7. إن فشل أول بناء، افتح سجل التشغيل في Actions وأرسل لي الخطأ لأصلحه.
